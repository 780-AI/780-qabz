Implementation phases

  1. 1

    Understanding the current system

    Read how the services work today, before changing anything.

    • system.html: the endpoints, config, code structure, database and known issues
  2. 2

    AI implements the core

    Everything the service needs before it has any business logic:

    • Config
    • Database
    • Logging
    • Monitoring (Prometheus, Grafana and the like)
    • gRPC gateway and server, with a hello endpoint
  3. 3

    Stage pipeline

    Build and deploy the core to stage.

  4. 4

    AI implement gRPC endpoints and providers

    Build everything qabz serves and everything it calls. The messages come from the current PB files.

    Inbound: what qabz serves
    • Inquiry and order for each bill type: water, electricity, gas, landline, mobile, and bill ID + pay ID
    • Saved bills (My Bills)
    • The list of bill types
    • PaymentComplete/OrderComplete, called by the payment service after the user pays
    Outbound: what qabz calls

    The providers below. Each one implements ProviderInterface, and the inbound endpoints reach a provider only through it.

    ProviderImplementationHow qabz reaches itWhat it does
    ParsianParsianProxygRPC to the existing parsian-v2 serviceInquiry, order, status check
    Jiring SwitchJiringProxygRPC to the existing jiring-switch serviceInquiry, order (only if Parsian is out of service), status check
    IrancellIrancellProxyThe existing irancell service: gRPC for inquiry and status, NATS for paymentInquiry, order, status check
    QabzinoQabzinoBuilt into qabzInquiry
    TavanirTavanirBuilt into qabzInquiry, bill document
    KarashabKarashabThird party, over HTTPInquiry and settlement, landline only
  5. 5

    Production pipeline

    Prepare the production pipeline, deploy, and test.

  6. 6

    Opening up the endpoints

    First, the inquiry endpoints

    Opened one by one.

    Then, the order endpoints

    Opened one by one, after some time. Management decides when.
